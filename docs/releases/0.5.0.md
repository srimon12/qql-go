# qql-go 0.5.0

Release date: 2026-06-19

## Summary

qql-go 0.5.0 introduces a production-ready security gateway layer with JWT authentication, a YAML policy engine for multi-tenant query filter injection, token-bucket rate limiting, hot-reloaded policy rules, and query templates. It also adds standalone `FUSION` statement syntax (making the `FROM` clause optional), late-interaction multivector (ColBERT/ColPali) capabilities, a high-throughput JSON payload converter (including a Python SDK HTTP client interceptor), and a Streamlit Security Playground web console. Core red-teaming fixes address nested CTE resolution scoping, named vector updates, and formula parser constraints.

106 files changed. 16,176 insertions, 1,080 deletions across 35 commits.

## Highlights

### Security Gateway & AST Filter Injection

The Connect RPC gateway now enforces resource access controls, tenant isolation, and audit logging directly at the query level before execution:

* **JWT Verification**: Validates caller tokens against JWKS configurations supporting RSA, EC, and Ed25519 signatures.
* **AST Transformation Policy Engine**: Automatically parses incoming QQL into ASTs, checks matching caller claims (e.g. `org_id`), and merges policy constraints (e.g. `inject.filters`) recursively into the AST query filters (supporting `=`, `!=`, `in`, and `not_in` conditions) before plan compilation.
* **Policy Reloading & Rate Limiting**: Zero-restart policy YAML reloading using `fsnotify` and token-bucket rate limiting per caller subject.
* **Audit Logging**: Generates detailed query audit logs in JSON format via structured context-passed logging.

### Late-Interaction Multivector Support

Enables multi-vector databases such as ColBERT or ColPali within QQL:

* **DDL Multivectors**: `CREATE COLLECTION` supports `WITH MULTIVECTOR (comparator = 'max_sim')` and HNSW indexing disabling (`WITH HNSW (m = 0)`) for fast inserts and reduced RAM.
* **Insert & Search named vectors**: Targets specific vector layouts (`dense`, `sparse`, `colbert`) inside insertions, updates, and prefetches.

```sql
CREATE COLLECTION docs (
  dense VECTOR(384, COSINE),
  colbert VECTOR(128, COSINE) WITH MULTIVECTOR (comparator = 'max_sim') WITH HNSW (m = 0)
)
```

### Standalone `FUSION` Statements

Simplifies prefetch-only search architectures:

```sql
WITH
  dense AS (QUERY 'care' USING dense LIMIT 200),
  sparse AS (QUERY 'care' USING sparse LIMIT 300)
FUSION RRF LIMIT 10 PREFETCH (dense, sparse)
```

No search target or base collection query is required. Standalone `FUSION` statements can also reside inside CTE subquery bodies.

### Payload Converter & SDK Interceptor

Automates legacy Qdrant client migrations to QQL:

* **`qql-go convert`**: Translates raw REST JSON payloads (stdin, file, or HTTP request format) to equivalent QQL.
* **SDK Interceptor**: A Python HTTP hook (`sdks/python/qql_intercept.py`) intercepting standard python SDK calls and translating them into QQL queries.
* **High-Throughput Conversion**: `pkg/qql` exposes a zero-allocation byte slice API to skip string copies in hot loops.

### Red-Teaming Core Gaps Closed

Hardened the compiler, parser, and execution plan engine:

* **Recursive Scoping**: Subqueries inside nested CTE chains recursively inherit parent scopes for correct execution plan compilation.
* **Named Vector Updates**: Support custom target vector mutations: `UPDATE collection SET VECTOR 'vector_name' = [...] WHERE id = <id>`.
* **Zero Division Default Value**: Adds default divisor support: `a / b [default=0.0]`.
* **Decay Function Validations**: Validates constant parameters and supports `decay` keywords as an alias for `midpoint` inside decay functions.

## Behavior Hardening & Constraints

| Feature | Change Description |
|---|---|
| Unquoted Payload Keys | Unquoted keys colliding with QQL reserved keywords (like `type`, `limit`, `using`) inside `INSERT` payload maps now raise parsing errors. Use quoted keys instead (`{'type': 'document'}`). |
| Non-Constant Decay Parameters | Non-constant expressions passed to decay `scale`, `midpoint`, or `decay` parameters now fail fast at compilation time instead of failing silently. |
| UUID format leniency | `ToPointID` falls back to `NewIDUUID` if string point IDs fail uint64 parsing, allowing mock IDs (e.g. `pt-1`) in CLI scripts. |

## Known limits

- `RERANK` is cloud-only. Local and external modes reject rerank queries.
- MMR applies to dense search and the dense leg of hybrid search. `USING SPARSE` and `RECOMMEND` do not accept MMR settings.
- `OFFSET` is not supported with `GROUP BY`.
- Local sparse weighting still differs from Python's FastEmbed BM25 path.
